## 1. О проекте

Система учёта для компании автотранспортных перевозок, разрабатываемая с нуля. Назначение:
- построение баланса и финансового результата;
- онлайн-формы для сотрудников-водителей (в первую очередь — отчёт по маршруту: пробег, заправки, топливо и т.д., ~10-15 полей);
- веб-интерфейс, доступный с телефона и компьютера через браузер (без нативных приложений).

**Область документа:** здесь рассматриваются только архитектурные вопросы (стек, окружения, хостинг, git). Детальное ТЗ на саму форму отчёта водителя (состав полей, валидация, логика) будет оформлено отдельным документом.

### Порядок разработки
1. Архитектура и окружение (текущий этап).
2. Онлайн-форма отчёта водителя — первый работающий модуль.
3. После стабилизации формы — переход к управленческой базе (баланс, финрез) и её интерфейсу.

## 2. Git и организация репозитория

- Хостинг репозитория: **GitHub**, приватный репозиторий, бесплатный тариф.
- Структура репозитория:
  ```
  /app-frontend      — код React-приложения
  /app-backend       — код backend API
  /infra             — docker-compose.yml, nginx-конфиги, миграции БД, .env.example
  /docs
    /meetings        — резюме встреч (стенограммы → саммари)
    /user-stories
    /tz.md
  README.md          — как поднять окружение с нуля
  ```
- Репозиторий — единственный источник правды: код, инфраструктура как код, документация и протоколы встреч лежат вместе.

## 3. Роль Claude в проекте

- **Claude (этот чат / claude.ai)** — планирование, обсуждение архитектуры, саммари встреч, черновики ТЗ и user stories.
- **Claude Code** — рабочий инструмент для самой разработки: клонирует репозиторий, видит одновременно код, инфраструктуру и документацию, пишет/редактирует код, коммитит, пушит.
- Стенограммы встреч и договорённости хранятся в репозитории (`/docs`) — так Claude Code имеет полный контекст при каждой сессии, и любой новый разработчик тоже может быстро войти в курс дела.
- **Доступ к серверу**: PO и разработчики могут работать на сервере интерактивно через SSH вместе с Claude Code (это не запрещено — риск здесь такой же, как при работе обычного разработчика руками, а не выше из-за участия ИИ). Разделение по окружениям:
  - **Дев/тест** — полностью открытый интерактивный доступ, можно свободно экспериментировать и пересобирать с нуля.
  - **Прод** — доступ есть, диагностика (логи, статус контейнеров) разрешена в любой момент, но любое изменение конфигурации сначала фиксируется в git (docker-compose, nginx-конфиг и т.д.) и применяется оттуда — через self-hosted runner автоматически или вручную накатыванием уже закоммиченного файла, а не прямой правкой "вживую" в SSH-сессии.

## 4. Хостинг

- Решение: **арендованный облачный VPS**, а не физическая машина. При текущей нагрузке (форма + позже небольшой бэкофис) облачный VPS выгоднее физического сервера по цене и гибкости — ресурс можно увеличить в любой момент без переезда.
- **Основной кандидат — Hetzner Cloud** (Германия/Финляндия): план CX22 — 2 vCPU, 4 GB RAM, 40 GB NVMe, ~€4-5/мес. Лучшее соотношение цена/мощность в Европе.
  - Расчётная нагрузка: до ~20 одновременных пользователей — конфигурация CX22 выбрана с большим запасом под эту нагрузку.
  - Риск: у Hetzner строгая антифрод-верификация, есть отзывы об отказах в регистрации пользователям из Украины. Не гарантированная проблема, но известный риск.
- **План Б при отказе Hetzner**: DigitalOcean или Vultr — чуть дороже (от ~$6/мес за похожую конфигурацию), но исторически мягче к верификации, проще интерфейс.
- ОС сервера: **Ubuntu Server 24.04 LTS** — официальные security-обновления до 2029 г. (можно продлить бесплатным Ubuntu Pro), лучшая документация и community для новичка в администрировании, полная официальная поддержка Docker.

## 5. Домен и DNS

- На утверждение собственникам предложены два варианта домена:
  - `giptrans.cc` — ~$15/год
  - `giptrans.co` — ~$8/год
- DNS — **Cloudflare**, бесплатный тариф: DNS-хостинг, защита от DDoS-атак и SSL-прокси, независимо от того, у какого регистратора куплен сам домен.

## 6. Окружения на сервере: прод и дев/тест

На одном физическом/облачном сервере — два изолированных окружения, каждое в своём Docker Compose стеке:

| | Прод | Дев/тест |
|---|---|---|
| Ветка git | `main` | `dev` |
| БД | своя копия Postgres | своя копия Postgres |
| Домен | основной домен | поддомен (например `dev.домен`) |
| Деплой | автоматически при push в `main` | автоматически при push в `dev` |

Изоляция — через разные Docker-сети/порты и переменные окружения, а не через раздельное железо.

## 7. Технологический стек (черновой, к уточнению)

- **База данных**: PostgreSQL в контейнере на сервере.
- **Backend API**: **Python / FastAPI**.
- **Frontend**: два отдельных интерфейса на разных технологиях, в зависимости от типа сценария:
  - **React-admin** — управленческие/административные экраны (баланс, финрез, CRUD) — рассчитаны на использование за компьютером, но не заблокированы для мобильных.
  - **React + TypeScript + Vite (кастомный)** — формы для полевого ввода данных (отчёт водителя) — mobile-first, но работают и с компьютера.
- **Auth**: Google OAuth (Published, базовые непривилегированные scope — email/имя, верификация Google не требуется), реализуется напрямую в backend; контроль доступа "кого пускать" — через собственный allow-list разрешённых email в БД приложения.
- **Файловое хранилище** (если понадобится, например для фото чеков АЗС): S3-совместимое хранилище.
- **Reverse proxy / TLS**: Nginx + Let's Encrypt (certbot).
- **Оркестрация**: Docker Compose.
- **Деплой**: GitHub Actions self-hosted runner, установленный на сервере — пуш в ветку триггерит пересборку и обновление соответствующего окружения (прод или дев).

## 8. Безопасность

Вопросы эксплуатационной безопасности (резервное копирование БД, базовая защита сервера, хранение секретов и переменных окружения) выносятся в отдельный документ и не входят в область текущей архитектуры.

## 9. Мониторинг и алерты

- **Внешний аптайм-мониторинг** — UptimeRobot (бесплатный тариф): проверка доступности домена каждые 5 минут, уведомления при падении.
- **Ресурсы сервера** — встроенные графики Hetzner Cloud (CPU, RAM, диск, сеть), без дополнительной установки.
- Отслеживание ошибок в коде (Sentry и т.п.) — не на старте, добавляется позже, когда формой начнут реально пользоваться водители.

## 10. Участники и роли

- **Собственники бизнеса** — утверждают ключевые решения (бюджет, домен, состав функционала верхнего уровня).
- **Product owner** — ведение ТЗ и архитектуры, координация разработки, основной постановщик задач для Claude / Claude Code.
- **Разработчики** — подключаются по мере роста проекта; доступ к репозиторию, работа по документации в `/docs`.
- **Claude / Claude Code** — роль описана в разделе 3.
